# TEST-02C — мобильная проверка BLE GATT для BT18-T

**Дата плана:** 12 октября 2026  
**Статус:** PENDING — ожидается результат с мобильного BLE-сканера.  
**Решение:** дальнейшие GATT-попытки и диагностику Bluetooth-адаптера через Windows прекратить. Windows TEST-02A уже PASS, TEST-02B завершён как NOT CONFIRMED после тайм-аутов.

## Предпосылки, подтверждённые владельцем

- Используются **два физических модуля** под именем `BT18-T`; первый был подключён отдельным кабелем, чтобы не отсоединять `EN` другого.
- Два значения AT: `99ea00f0da98` и `27ee00f0da98`.
- Windows ранее обнаружила BLE-адреса `98:DA:F0:00:EA:99` и `98:DA:F0:00:EE:27` соответственно: для каждой пары совпадают все 6 байтов в обратном порядке.
- Оба экземпляра, по отдельным результатам, рекламируют сервис `FFE0` и имя `BT18-T`; работоспособность GATT соединения **не подтверждена**.
- AT/UART 8/8 на одном экземпляре ранее выполнен при 9600 бод с `EN→GND`, без нажатия кнопки. Не считать режим `EN` другого экземпляра установленным только из-за смены кабеля.

## Метод

Подходит любой BLE Scanner на Android/iOS, который поддерживает просмотр сервисов/характеристик. Пример: **nRF Connect for Mobile** от Nordic Semiconductor.

1. Запитать **один** BT18-T, чтобы два одинаковых имени не путались. Не менять `EN` и не нажимать кнопку перед начальным сканированием.
2. Включить Bluetooth на телефоне, разрешить приложению необходимые права для BLE-сканирования; нажать **Scan**.
3. Найти `BT18-T`, отметить видимые имя, адрес (если ОС его показывает), RSSI, рекламируемый сервис `FFE0`.
4. Нажать **Connect**. Успех фиксировать только когда есть подтверждение соединения; одно рекламное объявление недостаточно.
5. После успешного соединения открыть список **Remote services / GATT** и записать реально обнаруженные `FFE0`, `FFE1`, `FFE2` и свойства характеристик (`Notify`, `Write`, `Read`, если присутствуют).
6. Зафиксировать скриншот подключённого устройства, список характеристик и при ошибке — текст ошибки или этап, на котором она произошла.
7. **Не нажимать Write, DFU, Pair/Bond, Enable Notifications** на этом этапе. Цель — только подключение и перечисление GATT. Если соединение не удалось, не присваивать аппаратный FAIL и не начинать многократные попытки без изменения условий.

На iOS система может скрывать/подменять аппаратный BLE-адрес собственным идентификатором; для сопоставления физических экземпляров используйте последовательное питание по одному, имя и при необходимости ранее известную пару адресов.

## Разграничение результатов

- **PASS-A:** рекламирование BLE `BT18-T`, `FFE0` (уже подтверждено Windows).
- **PASS-B:** мобильное приложение реально подключилось и выдало GATT-сервисы с характеристиками.
- **NOT CONFIRMED:** мобильная попытка подключения не завершилась. Это не доказывает брак модуля.
- **PENDING:** сквозная передача UART↔BLE и Classic/SPP, так как простое перечисление сервисов их не подтверждает.
